# Daiyu2 重构与可玩版路线图

本页只维护阶段目标与依赖，状态见 [current_milestone.md](current_milestone.md)。目标工程为 Daiyu2，参考旧游戏并按批准范围选择性迁入；阶段不是每次执行的任务级别。

| 阶段 | 目标 | 交付/退出条件 | 依赖 |
|---|---|---|---|
| M0 工作流与范围收敛 | 建立入口、工作流、现有边界和待批准方案 | 文档可接手，开发批准门槛清楚 | 当前仓库核实 |
| M1 斜向 2D 风格可玩版 | 新表现接入正式流程，并解决阻断基本操作的热点 | Windows 可运行目录、操作说明、最小交付检查与已知风险 | 用户批准 M1 |
| M2 试玩后收敛 | 根据用户实际反馈修正可读性、遮挡与持续性能 | 用户选定范围内的修复批次 | M1 包体和用户反馈 |
| 后续可选阶段 | 旧档迁移器、进一步模块拆分、移动端或发行 | 按实际需要单独立项 | 另行批准，不作为 M1 前提 |

## M1 内部批次

批次细节只在 [M1 执行计划](tasks/M1-01_oblique_2d_playable.md) 维护：

M1-01 是里程碑级总计划，以六个批次跟踪执行：A 依赖与粗模型核心 → B 正式场景引水/恢复闭环 → C 天气/生态/地下水/视野 → D 卡通表现与可读性 → E 完整玩家流程/存读档 → F Windows 集成交付。A 是必要核心准备，B 尽早完成纵向闭环；不把总计划当成一个小任务一次完成。

批次允许因真实依赖调整和合并，不要求每批全构建、独立审查或用户美术批准。有限水量、容量、引水与生态规则仍是边界。批准与执行状态只查当前阶段。

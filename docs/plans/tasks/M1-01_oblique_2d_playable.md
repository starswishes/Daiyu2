# M1-01：Daiyu2 斜向 2D 风格正式可玩版

级别：L3。原因：粗水模型、新保存契约，以及镜头/表现/玩家流程跨模块接入。唯一状态/批准记录见 [current_milestone.md](../current_milestone.md)。

## 目标与依据

在 Daiyu2 落地 [设计提案](../../design/oblique-2d-playable.md)，交付 Windows 可运行目录；直接开发正式链路，不另做独立样片。受 [技术规范](../technical_spec.md)、[ADR-001](../adr/ADR-001_oblique_2d_presentation.md) 和 [快速交付工作流](../workflow.md#fast-delivery) 约束。

工程基线见技术规范。以下旧入口仅为来源参考，不是本工程已有文件；开工须满足当前阶段授权和工作流的可恢复基线要求。

## 执行边界

开发批准后允许：按获批清单选择性迁入必要运行/玩家流程依赖，编写新表现脚本和相关 Shader/材质/贴图、创建正式场景及本工程 Windows 构建入口，进行针对实际热点的行为保持优化。新增小型纯表现组件沿用获批命名空间和单向依赖。保留当前模板与设置，不整体覆盖旧项目 Packages/ProjectSettings。

保护：有限账本、容量/来源限制、实际引水与生态反馈、核心无 Unity 依赖、源工程完整性、旧玩家档案/教程标记、资产 GUID。允许在新工程适配模拟推进、规划/容量模型及新快照，不要求旧 v4 档兼容；不迁移或修改旧真实玩家数据。依赖安装及 Git/发布操作按当前阶段中的独立授权执行。

粗模型的权威状态和新保存边界见 [技术规范](../technical_spec.md) 与 [ADR-002](../adr/ADR-002_coarse_water_and_new_saves.md)。不同时建设通用框架或拆分全部程序集；不新增无限造水、直接改地形、文明或新结局等玩法。

## 分批实施与验收

### A. 正式链路最小纵向闭环

- 在 `Assets/Daiyu/` 选择性迁入账本与必要生成规则；建立无 Unity 依赖的粗世界及唯一宿主，读取真实种子地图，直接接入拟定正式场景。
- 以地块/河段/节点账户、静态邻接和容量/水头近似决定转移；规划只改连接，实际转移只走账本。提交路径不重切地形、不重分三角库存。
- 同批接基础地形/水路显示、固定方向相机、拾取和引水输入；通过正式命令边界完成一次“选含水起点 → 规划 → 提交 → 真实来水 → 可见反馈”，不等美术完善再验证交互。
- 建立独立新档的最小快照，完整覆盖本批已存在的权威状态、时钟与速率余量；保存、恢复后继续推进。后续新增子系统同步扩展快照，不保留临时第二套保存链路。
- 退出条件：上述闭环可操作；来源不足/接收满正确拒绝或截断、真实转移守恒、规划不造水；恢复可继续，恢复失败保留当前局和原档。本批可在编辑器检查，不增加独立样片、玩家包或美术批准门槛。

### B. 规则与清爽卡通世界补齐

- 土壤、生态、天气、地下供泉和水况视野接同一个世界，催雨扣当地大气；固定业务 Tick 与分频速率有明确时间单位，新增状态/余量同步入档。
- 在 A 的显示/拾取链路上完善连续大色块地势、二维植被和简化岩石；固定透视相机提供平移/缩放，无玩家旋转/菜单环绕。
- 水带/积水区分规划、空路、来水、干涸；流纹表达真实方向，云雨/雾读取真实天气和视野。
- 分块合批、脏更新；操作预览保持实时，景物不抢拾取，重点水端/河路不被遮挡。
- 退出条件：生态、催雨与天气由真实数据推进；水路/干湿/生态可辨，显示与拾取一致，切换时资源可释放；新增系统恢复后可继续推进。

### C. 完整基础流程与独立新档

- 接入首界面、随机新局、简短教程、引水、催雨、生态反馈、暂停返回和存读档；教程条件改为新模型实际行为。
- 在 A/B 保存链路上补齐玩家进度与完整流程状态，按技术规范核对快照完整性；缓存重建，不把贴图网格入档，不另建一套保存系统。
- 数据隔离与候选世界切换遵循技术规范；对完整玩家流程检查恢复成功与失败保留。
- 退出条件：新局、重开、返回、保存/恢复可形成一致真实流程；旧玩家档案与标记保持原样。

### D. 集成与 Windows 交付

- 修复黑屏、操作入口缺失、显示/拾取不符、长时间卡顿等阻断问题；不为画风调整反复增加整套验证。
- 建立本工程 Windows 构建入口，不执行旧脚本或 Prepare，交付完整目录与启动/操作说明。
- 按工作流快速交付清单检查同一最终包体；交付运行内容变更后重建并更新受影响证据，不增加每批全构建。

# 斜向透视 2D 风格可玩版提案

本页维护已选设计方向，进度/开工批准只在 [当前阶段](../plans/current_milestone.md)，状态与接口边界见技术规范。

目标工程为 `Daiyu2`。文中旧玩法与镜头仅作参考，不作为本工程实现证据。

## 1. 已明确的方向

- 美术改为 2D 风格，保留斜向透视俯视。
- 目标是可游玩的现有游戏迁移，不先做独立风格小样。
- 采用 2.5D 承载，整体为清爽卡通；镜头固定方向，保留平移与缩放。
- 选择性复用旧核心与玩家流程，允许简化水模型；新档与旧档隔离，不要求读取旧 v4 档。
- 首版交付 Windows 完整基础流程；不做独立样片与完整回归。

## 2. 已选路线与计划细化

**技术选择：2.5D 承载，清爽卡通表达。** 复用可独立迁入的账本、地图生成、生态/天气规则与玩家流程，在新工程建立简化三维地势、二维景物与轻量水体。高耦合旧代码通过适配/重写接入，不把旧精细水面和开河几何链路整体搬回。2D 是最终画面方向，不要求所有物体只能是 Sprite。

### 镜头

- 真透视、固定斜俯视方向；以旧相机俯角约 50°、FOV 32° 为初始调参值。
- 保留平移与缩放，首版不提供自由旋转或四方向切换；缩放只改变观察距离，不引入新的旋转操作。
- 首界面沿用展示世界的功能，但采用固定朝向取景，不复用自动环绕；可保留云雨、水流等环境动态。
- 所有世界表现均按该固定相机设计，二维插片不需要多方向手绘资源集。

### 地貌与色彩

- 连续地表、清晰的大色块、少纹理与适度轮廓；逻辑六边形保留，避免整图每格画粗边框。
- 草地明快绿色，干地暖土色，水体青蓝，山石中性灰；干湿/生态状态差异清楚，不叠加水墨晕染或纸纹风格。
- 高差用简化体积与克制的坡面明暗表达，避免写实材质、碎三角噪声和强烈反光。
- 旧青玉 UI 组件/字体可复用，以清晰、卡通世界协调为准；不把旧主题配色当作新画风限制。

### 景物

- 树木、芦苇、草丛优先二维插片/合批；山石可保留简单体积并使用同一卡通风格。
- 按真实生态状态分组出现，减少高密度单株对象和每帧全图更新。
- 河岸和交互顶点留出空间；遮挡选中目标的景物可淡出，装饰不抢地形/水体拾取。

### 水体与天气

- 河流采用简化带状图形，真实来水与干涸可辨，少量流纹表示实际方向；未提交规划、已提交空路、实际水路分别表达。
- 湖泊/积水采用清楚的色块和简洁边缘，避免大量边缘细水条；不恢复精细岸线形变目标。
- 云雨/雾使用轻量分层表现，读取实际水况/天气/视野；只为动画生成的对象不额外记水。

## 3. 可玩范围与保护项

- 首版包含首界面、正式随机新局、简短教程、引水、催雨、生态反馈、暂停返回、存读档；旧流程按新模型适配，不照搬依赖精细几何的教程条件。
- 第一版仅 Windows；无新结局、文明玩法、地图生成扩展、第三方依赖或多端任务。
- 保留有限账本、水况视野、容量约束与实际收支。允许按粗粒度模型重设推进方式，不维持精细岸坎、动态地形切割和旧 v4 恢复语义。
- 新项目使用独立保存位置/键与版本化模型快照；不读写旧真实存档和教程标记，不承诺旧 v4 档直接导入。
- 粗模型与新表现按正式玩家链路分批落地，批次与验收见 M1 计划；变更门槛见技术规范。

## 4. 交付原则

真实玩家入口可以直接游玩，不能只通过美术预览参数看新画面。可用性优先于纹理丰富度，清晰水路优先于景观密度。

目标预算为基本交互持续顺畅，争取 30FPS；这是目标，不是现有实测承诺。执行 [快速交付策略](../plans/workflow.md#fast-delivery)，跳过完整验证矩阵；若仍有阻断操作的长卡顿，按部分完成报告并优先修复。
